# 原始字段与共同费用

Cashflare 提供账本运行环境。账单解析、跨平台去重和个人费用分摊需要结合原始交易证据审查，仓库不包含个人导入脚本或自动猜测用途的规则。

记录时分别保留交易对方显示名、平台交易分类、商品说明、备注、原始交易号和来源文件/行号。平台的“教育培训”“酒店旅游”标签，以及商家公司名称，不能直接证明实际买了课程或住宿。其他入款中的比赛备注只是关联证据，不会自动变成某笔付款的已确认用途。同一显示名或脱敏账号也不保证同一实体。

共同费用应按事件设置独立往来账户，例如 `Assets:Pending:SharedExpenses:ExampleEvent`：

1. 向商家统一付款时，借记事件往来、贷记实际资金账户。
2. 收到参与者分摊款时，借记实际资金账户、贷记同一事件往来；这部分不是个人收入。
3. 明确本人份额后，另做一笔非现金结算，借记消费科目、贷记事件往来。
4. 若有多组可能的收款来源，保留付款往来，并把未匹配收款记入 `Liabilities:Pending:SharedCollections:*`，不要随意相抵。

[可运行的虚构示例](../examples/shared-expenses.beancount)展示统一付款 300 元、收回两份各 100 元、暂计本人 100 元的过程。示例不由空白主账本包含。

收付款差额不必然是本人消费：它可能包含未收到的款项、预收款、退款或混合用途。暂定分摊可用 `!` 标记、`allocation-review` 标签及判断依据，后续有新证据时再调整。事件往来负余额表示暂收款尚未分配，不应直接转成收入。其他账户间划转、退款、借款、报销和家人代付应分别核对，保持真实资金来源不变。

使用同一交易号防止重复导入。重新分类时保存原科目及判断依据，核对每笔银行/钱包分录、原始交易字段和余额断言，而不只是比较总额。所有原始账单、账本、备份和分析报告只存放于私有数据目录。
